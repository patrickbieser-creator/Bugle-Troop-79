Project Overview

Troop 79 currently has no central public web presence. This project establishes a full website serving both prospective members of the public and—more importantly—the active troop community: scouts, parents, and leaders in Milwaukee’s Shorewood and Bayview neighborhoods.

The site brings together four existing information streams (advancement records, the weekly Bugle newsletter, the troop calendar, and event photos) into one coherent, well-maintained destination. A members-only section keeps advancement data private while the public-facing pages project a welcoming, professional image to prospective families.

Proposed Domain

troop79bsa.org — appears available for registration. Confirm at Namecheap or Google Domains before proceeding. The .org extension is appropriate for a non-profit unit.

Primary Goal

A central hub for current troop members: easy access to advancement status, upcoming events, photos, and the weekly Bugle — all in one place.

Secondary Goal

A welcoming public-facing presence for prospective scouts and families in the Milwaukee area, with clear information about joining.

Managed By

A small group of troop leaders with admin access. No technical expertise required for day-to-day content updates (Bugle upload, event entry, photo links).

Audiences

Current Members Primary
  • Scouts checking advancement progress
  • Parents tracking rank & merit badge status
  • Leaders managing calendar events
  • Anyone reading this week’s Bugle
Prospective Members Public

  • Eagle Scout alumni reconnecting

Advancement Module

This is the most complex feature of the site. Advancement data lives today in a Google Sheet with comprehensive rank, requirement, and merit badge information. The plan is to import this into a proper database and expose it through a clean scout-facing UI.

Data Import

  1. Share Google Sheet (view-only) with the development team
  2. Analyze column structure: scout names, ranks, requirement IDs, completion dates, merit badge names, partial completions
  3. Design the database schema to match (see below)
  4. Build a one-time import script to migrate all historical data
  5. Validate imported data against the Sheet row by row
  6. Going forward: admin triggers a manual sync from the Sheet, or data is entered directly in the site

Database Schema (Proposed)

Scouts
  • Name, date of birth, patrol
  • Active / inactive status
  • Date joined, Eagle date (if applicable)
Ranks & Requirements
  • Rank name (Tenderfoot → Eagle)
  • Per-requirement: ID, description, completion date
  • Rank earned date
Merit Badges
  • Badge name, Eagle-required flag
  • Status: earned (date) or partial
  • Partial: requirements completed & remaining
  • Counselor name (optional)
Positions of Responsibility
  • Position name, start/end dates
  • Required for Star, Life, Eagle

Scout Advancement View

When a member looks up a scout, they see a dashboard with four panels:

Current Rank Card

Badge image, rank name, date earned. Visual progress bar toward next rank showing % of requirements complete.

Next Rank Requirements

Checklist of all requirements for the next rank: completed items (with date) and remaining items highlighted.

Merit Badges Earned

Grid of earned badges with date. Eagle-required badges clearly marked. Count toward Eagle requirement (21 total, 13 Eagle-required).

Partial Merit Badges

In-progress badges with requirement-level detail: which requirements are done and which remain.

Calendar

The troop currently maintains its calendar as an ICS file in Google Sheets. The goal is to eliminate that sheet entirely and manage events directly through the website’s admin interface.

Event Entry (Admin)
  • Title, date/time, location
  • Event type (meeting, campout, service, fundraiser, high adventure)
  • Description & what to bring
  • Cost (if any)
  • RSVP deadline (optional)
Public Calendar View
  • Monthly grid view + list view toggle
  • Filter by event type
  • Click event for full detail
  • ICS subscribe link (replaces the Google Sheet)
  • Google Calendar “Add” button per event

Migration from Google Sheets

  1. Export existing ICS data from the Google Sheet
  2. Import all future events into the site database
  3. Verify events are correct
  4. Retire the Google Sheet — leaders use site admin going forward

The Bugle

The weekly Bugle newsletter is already produced as a polished HTML file and distributed via EmailOctopus. The website does not replace that workflow — it provides an additional display surface.

Current Edition

The most recently uploaded HTML file is rendered directly on the /bugle page. No editor needed — the leader uploads the same HTML file that goes to EmailOctopus.

Archive

All past editions are stored and browsable by date. The archive is automatically built from uploaded files — no extra steps required.

Publish Workflow

  1. Leader produces HTML file (existing process, no change)
  2. Send via EmailOctopus as usual
  3. Log into site admin → upload same HTML file
  4. Site displays it immediately as current edition; previous edition moves to archive

Recommended Tech Stack

This is a dynamic web application (not a static site) because it needs a database, authentication, calendar management, and file uploads. The recommended stack is familiar territory — it mirrors the SecondBrain project already in use.

Layer Choice Purpose Est. Cost
Framework Next.js (App Router) Full-stack React — pages, API routes, server components Free
Database PostgreSQL via Neon Advancement data, events, gallery, Bugle archive Free (0.5 GB) → $19/mo if needed
ORM Prisma Type-safe DB access, migrations, schema management Free
Auth Shared password (env var) Simple members-only gate; no individual accounts Free
File Storage Vercel Blob or Cloudflare R2 Bugle HTML files, future logo/assets ~$0–$5/mo
Hosting Vercel Deploys automatically from GitHub; global CDN Free hobby → $20/mo Pro
Domain troop79bsa.org Register at Namecheap or Google Domains ~$12/yr

Estimated total running cost: ~$12/year to start (domain only). Scales to ~$30–$50/month if traffic or storage grows significantly — unlikely for a troop website.

Why Not WordPress or Squarespace?

The advancement module requires a custom database schema and a tailored query interface — not something a page builder handles well. A custom Next.js build gives full control over the advancement dashboard and means the site can evolve as the troop’s needs change, without platform limitations or per-seat licensing fees.

Open Questions

These items need a decision from troop leadership before or during development.

Decision Needed

Google Sheet access: Share the advancement Google Sheet (view-only) with the developer to analyze the schema before Phase 3 begins. This determines database design.

Decision Needed

Domain registration: Confirm troop79bsa.org is available and register it. Recommend using the troop’s email address as the registrant, not an individual leader’s personal account.

Decision Needed

Logo & colors: Troop logo to be provided for use on the site. Confirm whether there are official troop colors beyond BSA standard palette.

Decision Needed

Advancement data going forward: After import, does the Google Sheet remain the source of truth (admin syncs periodically) or does data entry move entirely to the website? The latter is cleaner but requires leaders to change their workflow.

Decision Needed

Photo gallery scope: Google Photos albums will be linked (not embedded). Who maintains the list of albums shown on the site — any leader, or a designated “gallery admin”?

To Confirm

Bugle members gate: Should the full Bugle archive be members-only, or just the current edition? Some troops make past newsletters fully public as a recruiting tool.

To Confirm

Roster privacy: Advancement lookup shows scout names. Confirm that all scouts’ parents are comfortable with names being visible to anyone who has the shared troop password (not to the general public).
